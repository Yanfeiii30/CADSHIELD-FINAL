How Naive Bayes Works

Definition: Naive Bayes is a supervised, probabilistic machine-learning classifier based on Bayes' Theorem. It's called "naive" because it assumes every word in a comment pushes the aggressive/safe decision independently of every other word — it ignores grammar and word order entirely. It has to be trained: everything it "knows" comes from counting word frequencies across the 51,920 labeled training comments, nothing is hand-written.

Show the step-by-step computation (real numbers from this model)
1
Tokenize

Lowercase the text, strip punctuation, remove stopwords ("a", "the", "is"...). Words following a negation ("not", "never", "don't"...) within a 3-word window are tagged separately (e.g. "not_stupid") instead of being scored the same as the bare word "stupid".

2
Class Prior — baseline, before reading a single word

Computed once from real training document counts:

✓ Exact formula — naive_bayes.js / train.py
log_prior(safe) = log(38,940 / 51,920) = -0.2877
log_prior(aggressive) = log(12,980 / 51,920) = -1.3863

Starts biased toward "safe" — 75% of training comments are safe.

3
Score each matched word — Laplace / add-1 smoothing

For every token that exists in the 99,561-word trained vocabulary:

✓ Exact formula — naive_bayes.js / train.py
ll(class) = log( (word count in class + 1) / (total words in class + vocab size) )

Real totals used: 1,604,569 safe-class words, 427,093 aggressive-class words. The +1 (Laplace smoothing) stops a word NB has never seen in one class from getting a log(0) = −infinity score.

4
Dampen negated words

A "not_X" token only ever appears in a handful of training examples, so its learned class split is noisy. Its two log-likelihoods are pulled 75% of the way toward their average, so a single negated word can't single-handedly flip the verdict.

5
Add it all up
✓ Exact formula — naive_bayes.js / train.py
score_safe = log_prior(safe) + sum of every matched word's ll(safe)
score_aggressive = log_prior(aggressive) + sum of every matched word's ll(aggressive)
6
Convert to a probability — softmax
✓ Exact formula — naive_bayes.js / train.py
P(aggressive) = e^(score_aggressive) / ( e^(score_safe) + e^(score_aggressive) )
7
Decision
P(aggressive) ≥ 50% → Naive Bayes says AGGRESSIVE
How VADER Works

Definition: VADER (Valence Aware Dictionary and sEntiment Reasoner) is a rule-based sentiment-analysis tool — not machine learning, and it has no training step. It scores text using a fixed, hand-built dictionary of words with pre-assigned positive/negative "valence" scores, plus grammar-aware rules for negation, intensifiers, capitalization, and punctuation.

Show the step-by-step computation
1
Expand slang

Joined internet slang is split before scoring, e.g. "shutup" → "shut up", "kys" → "kill yourself".

2
Look up each word's base valence

Every word found in the lexicon gets a hand-assigned score, e.g.:

"hate" = -3.2 "stupid" = -2.9 "beautiful" = +2.8 "great" = +3.1
3
Apply modifiers, in order
ALL CAPS emphasis: ±0.733 if the word is capitalized and the sentence has other caps too
Booster words nearby: "very"/"so" = ±0.29, "extremely"/"absolutely" = ±0.44, scaled by distance
Negation 1-3 words before: valence × -0.74 — this is why "not beautiful" reads negative
4
Punctuation boost

Each "!" in the text adds a small push in the direction the sentiment is already leaning (capped at 4 exclamation marks).

5
Sum and normalize

Add every word's final valence together, then squash it to a -1..+1 "compound" score:

✓ Exact formula — vader.js / vader_helper.py
compound = sum / sqrt( sum² + α ) — α ≈ 10-15
6
Sarcasm correction

If a known sarcastic phrase is detected ("oh wow", "real genius", "yeah right"...) and the compound reads positive, it gets flipped negative — sarcastic praise is treated as aggression, not genuine sentiment.

7
Backhanded-insult override

If the sentence has "but/however/although" AND one clause directly insults "you" (e.g. "you are worthless"), only THAT clause's compound is used — a trailing compliment can't cancel out a leading insult.

8
Decision
✓ Exact formula — vader.js / vader_helper.py
aggression_score = max(0, -compound) — only negative sentiment counts; positive text always scores 0
aggression_score ≥ 50% → VADER says AGGRESSIVE
Why 60% Naive Bayes / 40% VADER?

The weights in R_score = 0.6 × NB + 0.4 × VADER are set in proportion to how much each algorithm can be trusted on its own, measured on the same 12,980 held-out test comments:

Algorithm (solo)PrecisionRecallF1-Score
Naive Bayes85.13%77.60%81.19%
VADER57.40%58.43%57.91%
NB's share of combined F1 = 81.19 / (81.19 + 57.91) = 81.19 / 139.10 ≈ 58.4% — the chosen 60% weight sits within ≈1.6 points of that ratio, rounded to a clean number instead of an oddly-precise 58.4/41.6 split.

Naive Bayes' F1 (81.19%) is roughly 23 points ahead of VADER's (57.91%) — it actually learned real word-frequency patterns from 51,920 labeled training comments, while VADER is a fixed, hand-built sentiment lexicon with no training step of its own. Since NB is the substantially stronger standalone model, it gets the majority vote (w1 = 0.6); VADER isn't discarded, but its weaker, un-trained signal only gets to nudge the score (w2 = 0.4), not dominate it.

VADER still earns its 40%: it catches genuine aggression that NB's bag-of-words model misses on its own — see the worked example in the Evaluation tab, where NB alone scores a real insult as SAFE (33.86%) but VADER's negation-aware sentiment handling correctly reads it as hostile (75.81%), and the blend flips the final verdict to AGGRESSIVE. The actual proof this 60/40 split works: blending at this ratio measurably beats Naive Bayes alone on the same held-out test set — Precision rises from 85.13% → 88.82% and F1 from 81.19% → 81.42%, at a small Recall cost (77.60% → 75.16%). The ratio wasn't found by grid-searching every possible weight combination — it's a direct, interpretable reflection of each algorithm's own measured reliability, and that reflection held up when tested.

Why not give VADER more than 40%? It was tried — pushing VADER's weight higher made the blended result less reliable, not more. That tracks with the numbers above: VADER's standalone F1 (57.91%) trails Naive Bayes' (81.19%) by ~23 points, so the more influence VADER's weight gives it, the more of its own mistakes (mainly false positives — sentiment-only scoring has no memory of real aggression patterns the way a trained model does) get carried into the final Hybrid score instead of being corrected by NB. 60/40 is the point where VADER still meaningfully corrects NB's blind spots (see the worked example above) without letting VADER's weaker judgment start overriding NB's.

Worked Examples — Aggressive vs. Safe

Two real sentences, run through every formula above, start to finish — the exact same wording except one word, so you can see what negation alone changes.

Example 1 — AGGRESSIVE: "You are not beautiful"
A
Naive Bayes

Tokenize: "you" and "are" are stopwords, removed. "not" triggers negation, consumed. "beautiful" gets tagged not_beautiful.

not_beautiful never showed up often enough in training to earn its own vocabulary entry — zero words matched. With no evidence at all, NB falls back entirely to the class prior:

P(aggressive) = aggressive docs / total docs = 12,980 / 51,920 = 25.0%
B
VADER

Tokenize (VADER keeps stopwords): "You", "are", "not", "beautiful". Only "beautiful" is in the lexicon.

base valence = +2.8
negated by "not" 1 word before → +2.8 × -0.74 = -2.072
compound = -2.072 / sqrt(2.072² + 10) = -2.072 / 3.781 ≈ -0.548
aggression_score = max(0, 0.548) = 54.8%
C
Hybrid

Normally this would blend 0.6 × 25.0% + 0.4 × 54.8% = 36.9% — but NB matched zero words here, so its 25.0% isn't real evidence, just the untouched class prior. The zero-evidence guard catches exactly this case and skips the blend, using VADER's read directly instead:

Hybrid = VADER = 54.8% ≥ 50% → AGGRESSIVE ✓
Example 2 — SAFE: "You are so beautiful"
D
Naive Bayes

Tokenize: "you", "are", "so" are all stopwords, removed. No negation this time — "beautiful" stays as itself (not tagged) and does exist in the trained vocabulary.

safe total = log_prior(safe) + ll(safe) = -0.2877 + -10.2710 = -10.5587
aggressive total = log_prior(aggressive) + ll(aggressive) = -1.3863 + -9.7403 = -11.1266
P(aggressive) = softmax(safe total, aggressive total) = 36.2%

Notice this is still nowhere near 0% — "beautiful" is a genuinely positive word, but its rare, class-imbalanced training counts give it a small noisy lean toward "aggressive" (the same effect covered earlier for "worthless but beautiful"). 36.2% stays safely under the 50% threshold, so NB alone still calls this SAFE.

E
VADER

Tokenize: "You", "are", "so", "beautiful". "beautiful" matches the lexicon; "so" is a booster word directly before it.

base valence = +2.8
boosted by "so" (+0.293, adjacent) → 2.8 + 0.293 = +3.093 (no negation word this time — nothing flips it)
compound = 3.093 / sqrt(3.093² + 10) = 3.093 / 4.423 ≈ +0.699
aggression_score = max(0, -0.699) = 0.0% (positive compound never counts as aggression)
F
Hybrid

NB matched a real word this time ("beautiful" is in the trained vocabulary), so the zero-evidence guard doesn't apply — the normal 60/40 blend runs:

Hybrid = 0.6 × 36.2% + 0.4 × 0.0% = 21.7% < 50% → SAFE ✓

Same sentence, same words, one negation removed — VADER's read flips from 54.8% aggressive to 0.0% safe, and the Hybrid verdict flips with it. This is exactly what "negation flips meaning" refers to throughout the rest of this extension.
