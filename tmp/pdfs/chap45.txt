RESULTS AND DISCUSSION
Chapter Introduction
This chapter presents the results of the development and evaluation of the
proposed real-time cyber-aggression detection and mitigation system implemented
as a Chromium-based browser extension.
The data gathered were analyzed in
relation to the study's specific objectives set in Chapter I — the comparative
classification performance of the proposed hybrid Naive Bayes and VADER model
against single-algorithm approaches in terms of precision, recall, and F1-score, and
the level of software quality of the system as evaluated by end users and IT experts
under the ISO 25010 standard. This chapter includes the feedback gathered from
both groups of respondents through structured survey questionnaires, as well as
observations from internal algorithmic testing and external evaluative validation. The
discussion throughout this chapter focuses on how the system's components —
namely its text extraction module, hybrid classification engine, and mitigation
features including the blocklist and whitelist — address the problems identified in
Chapter I, and on how well the system performed during technical and user-based
testing.
Presentation and Discussion of Results
SOP 1 - Development of the Cyber-Aggression Detection and Mitigation
System
This section presents the development of the proposed real-time cyber-
aggression detection and mitigation system using a hybrid approach of Naive Bayes
and VADER. The system was implemented as a Chromium-based browser

extension that analyzes eligible user-generated text and blurs content identified for
filtering.
The discussion covers the system’s architecture, interface, text-filtering
features, reveal controls, user-defined blocklist and whitelist, detection logs, statistics,
and Expert Mode. Screenshots illustrate the implemented features, while the
functional testing results describe their observed operation under the documented
testing conditions.
System Development and Architecture
The project separated offline model training and evaluation from browser-
based operation. Python was used to prepare the labeled dataset, train the Naive
Bayes classifier, and generate algorithm evaluation results. The extension was
implemented using JavaScript, HTML, and CSS under Manifest V3. Its components
included a background service worker, content scripts, algorithm modules, filtering
and page-selection rules, local storage, and a popup interface. This separation
allowed text classification and visual mitigation to operate within the browser without
a remote classification server.
The training materials used a binary dataset derived from the Jigsaw Toxic
Comment Classification Challenge. Records were labeled aggressive when at least
one of the six source categories was positive: toxic, severe toxic, obscene, threat,
insult, or identity hate. The supplied project dataset contained 64,900 samples,
comprising 48,675 non-aggressive and 16,225 aggressive samples. A stratified
80/20 division produced 51,920 training samples and 12,980 testing samples. The
Naive Bayes training procedure used class priors, word frequencies, and Laplace
smoothing. The extension loaded a stored JSON model containing the parameters
required for local scoring.
According to the development record, the researchers integrated the model-
scoring components with webpage scanning, custom filtering, blur and reveal

controls, logs, and interface features. Refinements addressed repeated scanning of
dynamic pages, short aggressive expressions, aggressive questions, accidental
scanning of the extension interface, private-page exclusions, tab activation, and
conflicts between custom word lists. The resulting implementation used scoped
mutation handling, duplicate-element tracking, shared configuration, and partial text
masking. These changes were supported by automated regression checks and a
controlled browser demonstration.
Text Extraction and Hybrid Detection
The text extraction component used the Document Object Model (DOM) to
locate eligible text nodes. Initial scans were followed by MutationObserver-based
monitoring of newly added content. The implementation grouped scanning work into
batches and delayed repeated mutation scans until updates settled, reducing
unnecessary repeated traversal. It also traversed accessible open Shadow DOM
structures. Page-selection rules excluded interface elements, editable controls, and
designated private communication areas. The implemented rules did not establish
that all publicly displayed text or every type of post could be scanned.
User-defined filtering rules were checked before algorithm scoring. For text
that proceeded to the algorithms, the runtime retained the first 128 whitespace-
separated tokens. The Naive Bayes and VADER-derived components then applied
their respective preprocessing and scoring procedures. The browser implementation
included custom handling for selected joined expressions, negation, sarcasm cues,
and other contextual patterns. These mechanisms represented implemented rules;
they did not demonstrate complete understanding of sarcasm or context.
For the normal hybrid scoring path, the two outputs were combined using the
following fixed weighting:
Hybrid score = (0.60 x Naive Bayes score) + (0.40 x VADER-derived
aggression score)


=== PDF PAGE 5 ===

The fixed classification threshold was 0.50. Under the score-based decision
rule, a final score of at least 0.50 resulted in an aggressive classification, while a
lower score resulted in a non-aggressive classification. The interface also supported
Naive Bayes-only and VADER-only modes. In Hybrid mode, the runtime included a
VADER-only fallback when no trained Naive Bayes vocabulary features matched the
text, as well as additional language and self-directed-distress rules that could modify
the final decision. Custom blocklist and whitelist rules could also override the
algorithm path. Therefore, the weighted formula described the principal scoring
mechanism rather than every possible filtering decision.
The VADER-derived browser module used a customized JavaScript lexicon
and rules. Its negative compound score was transformed into a nonnegative
aggression-related score using max(0, -compound). This score served as a signal
for the system rather than proof that negative sentiment necessarily represented
aggression. The offline notebook and deployed runtime were treated separately
because the runtime included additional rules and the 128-token limit.
Privacy controls were implemented through configured hostname exclusions,
path-based checks, and rules for selected private communication elements. The
supplied configuration excluded designated messaging, email, document, and other
private-service areas. These controls reduced scanning in configured areas; the
available evidence did not establish universal recognition of every private page on
the internet.

The implementation addressed SOP 1 by connecting local text extraction,
Naive Bayes and VADER-derived scoring, custom filtering, visual mitigation, and

and documented functional examples, rather than by claims of universal detection or

SOP 2 - Performance Evaluation of the Hybrid Model
This section presents the performance evaluation of the proposed hybrid
model compared with the individual Naive Bayes and VADER approaches. The
evaluation determines how effectively each approach detects cyber-aggressive user-
generated text based on precision, recall, and F1-score.
The discussion covers the testing dataset, performance metrics, confusion
matrices, and hybrid-weight comparison. Tables and figures present the recorded
results, while the accompanying textual discussion explains the strengths, errors,
and limitations observed during evaluation.
Evaluation Data and Procedure
All three approaches were evaluated using the same 12,980 labeled testing
samples, consisting of 3,245 aggressive samples and 9,735 non-aggressive
samples. Aggressive text was treated as the positive class. The evaluation applied a
fixed classification threshold of 0.50 to all three approaches, with the hybrid
configuration using 60% Naive Bayes and 40% VADER.

2.1 Precision
The hybrid model achieved the highest precision at 88.82%, followed by

had the highest proportion of correct aggressive classifications among the samples it
flagged.
For a filtering system, higher precision is useful because it reduces the
unnecessary filtering of non-aggressive text. The result shows that the implemented

hybrid configuration produced fewer false positives than either standalone approach
within the evaluated dataset.
2.2 Recall
Naive Bayes obtained the highest recall at 77.60%, followed by the hybrid
model at 75.16% and VADER at 58.43%. Naive Bayes therefore detected a larger
proportion of the actual aggressive samples.
Although the hybrid model achieved higher precision, it missed more
aggressive samples than Naive Bayes. This finding indicates a trade-off between
reducing incorrect aggressive classifications and detecting as many aggressive
samples as possible.
2.3 F1-Score
The hybrid model obtained the highest F1-score at 81.42%, followed by
Naive Bayes at 81.19% and VADER at 57.91%. This result indicates that the hybrid
configuration achieved a slightly better balance between precision and recall.
The improvement over Naive Bayes was approximately 0.23 percentage
points. This was a small observed difference and cannot be described as statistically
significant because no significance test or confidence interval was provided.

Hybrid Weight Selection and Operational Comparison
The 60% Naive Bayes and 40% VADER weighting was selected as a
performance-proportional and operationally balanced configuration. Naive Bayes
was assigned the larger contribution because it was trained using the project's
labeled aggressive and non-aggressive dataset and achieved a standalone F1-score
of 81.19%. In comparison, the general-purpose VADER sentiment analyzer obtained
an F1-score of 57.91% and was used as a complementary sentiment signal.
The proportional contributions of the two algorithms were calculated from
their standalone F1-scores as follows:
Naive Bayes proportion = 81.19 / (81.19 + 57.91) = 58.37%
VADER proportion = 57.91 / (81.19 + 57.91) = 41.63%
The resulting proportions were rounded to 60% for Naive Bayes and 40% for
VADER to produce a simple, interpretable, and reproducible configuration. The
hybrid score was calculated as (0.60 × Naive Bayes score) + (0.40 × VADER score).
A subsequent sensitivity analysis compared 21 possible weight combinations.
The 65% Naive Bayes and 35% VADER configuration obtained the highest tested
F1-score of 81.55%, while the implemented 60/40 configuration obtained an F1-
score of 81.42%. Table 6 compares the two configurations in terms of classification
performance and error counts.

evaluation, followed by a single assessment using an untouched testing set.
Interpretation of the Results
The hybrid model achieved the highest precision and a slightly higher F1-
score than Naive Bayes, while Naive Bayes achieved the highest recall. The hybrid
approach was most beneficial in reducing false positives within the evaluated
dataset. Its performance did not exceed Naive Bayes on every metric.
These findings represent the offline notebook evaluation, which processed
complete text samples without custom blocklist and whitelist overrides. The browser

extension additionally used customized processing rules, a 128-token limit, and a
stored Naive Bayes model that differed from the notebook-generated model.
Therefore, these results do not establish the end-to-end performance of the exact
deployed extension.
No separate validation set was used, and the same testing subset informed
both the initial weighting decision and the subsequent weight comparison. The
reported hybrid results should consequently be interpreted as a test-informed
comparison rather than an independent final evaluation of a configuration selected
without reference to the testing data.

Implementation of the Algorithms
The proposed system implemented a hybrid approach that combined Naive
Bayes classification with a VADER-derived sentiment analysis component to identify
aggressive user-generated text. Both components analyzed the eligible input and
produced separate numerical scores. These scores were combined using fixed
weights to support the system’s classification and filtering decisions.
Implementation of Naive Bayes


=== PDF PAGE 45 ===
COLLEGE OF COMPUTING STUDIES
45
The Naive Bayes classifier used parameters learned from labeled aggressive
and non-aggressive text during offline training. These parameters included class
priors and word likelihoods, which were stored in a JSON model and loaded by the
browser extension.
During text analysis, the component performed tokenization, lowercasing,
stop-word removal, and additional implemented preprocessing rules. It matched the
resulting features against the stored vocabulary and calculated class scores using
the learned parameters. These scores were converted into an estimated probability
that the input belonged to the aggressive class.
In Naive Bayes-only mode, the system used this probability directly for
classification. A score of at least 0.50 produced an aggressive classification, while a
lower score produced a non-aggressive classification.
Implementation of VADER
The VADER-derived component used a customized JavaScript sentiment
lexicon and contextual rules to assess the sentiment expressed in the input. These
rules included handling for negation, intensifiers, selected slang expressions, and
sarcasm cues.
The
component
produced
a
compound
sentiment
score,
which
was
transformed into a nonnegative aggression-related score using the following
expression:
VADER-derived aggression score = max(0, −compound score)
For example, a compound score of −0.60 produced an aggression-related
score of 0.60. A positive compound score produced a transformed score of zero.
This transformation allowed negative sentiment to contribute to the classification


=== PDF PAGE 46 ===
COLLEGE OF COMPUTING STUDIES
46
process. However, negative sentiment alone did not establish that the input was
aggressive.
In VADER-only mode, the transformed score was compared with the same
fixed classification threshold of 0.50.
Integration of the Hybrid Approach
The hybrid approach combined the individual scores through weighted
integration. Naive Bayes contributed 60% of the combined score, while VADER
contributed 40%. The principal hybrid calculation was expressed as follows:
Hybrid score = (0.60 × Naive Bayes score) + (0.40 × VADER-derived
aggression score)
Both components received the same eligible text, while each applied its own
preprocessing and scoring procedures. Their outputs were combined after scoring.
This arrangement allowed the classification patterns learned by Naive Bayes and the
sentiment information provided by VADER to contribute to a common decision.
The 60/40 weighting was selected after reviewing the standalone evaluation
results and before conducting the full weight comparison. Naive Bayes received
greater influence because it demonstrated stronger standalone performance in that
evaluation. The selected weighting served as the implemented design choice and
was not established as the highest-performing weight combination.
Under the standard weighted decision rule, a hybrid score of at least 0.50
resulted in an aggressive classification. A score below 0.50 resulted in a non-
aggressive classification. The weights and classification threshold remained fixed
during browser operation.
Application within the Browser Extension


=== PDF PAGE 47 ===
COLLEGE OF COMPUTING STUDIES
47
The
extension
extracted
eligible
user-generated
text
from
supported
webpage areas and checked the user-defined blocklist and whitelist before algorithm
scoring. A blocklist match triggered filtering. When no blocklist match took priority, a
whitelist match could exempt the text from algorithmic filtering.
For text that proceeded to algorithm analysis, the extension retained the first
128 whitespace-separated tokens. It obtained the Naive Bayes and VADER-derived
scores and applied the decision rule associated with the selected mode: Naive
Bayes, VADER, or Hybrid.
The browser implementation also included exceptions to the principal hybrid
calculation. When the loaded Naive Bayes model had no vocabulary matches for the
analyzed text, Hybrid mode used the VADER-derived score as a fallback. Additional
language and self-directed-distress rules could modify the hybrid decision. These
mechanisms operated separately from the fixed classification threshold.
Following the final decision, the extension blurred text identified for filtering
and provided a control for revealing and re-hiding it. Text classified as non-
aggressive remained readable. Detection logs and statistics recorded the system’s
activity, allowing users to inspect the resulting classifications and filtering outcomes.
Chapter 5
SUMMARY OF FINDINGS, CONCLUSION, AND RECOMMENDATIONS
This chapter presents the summary of the study conducted to design,
develop, and evaluate a real-time cyber-aggression detection and mitigation system
implemented as a Chromium-based browser extension. The primary purpose of the
study was to address the reactive, server-dependent, and single-algorithm limitations
of existing cyber-aggression detection tools by developing a lightweight, privacy-


=== PDF PAGE 48 ===
COLLEGE OF COMPUTING STUDIES

preserving, client-side framework that combines Naive Bayes classification and
VADER sentiment analysis to automatically detect and mask cyber-aggressive user-
generated content to reduce users’ exposure to it.
Summary of Significant Findings
This section presents the significant findings of the study in direct response
to the Statement of the Problem raised in Chapter I. The findings were drawn from
the system’s development and functional testing, algorithm evaluation, and the
survey assessments gathered from end-users and IT experts.
1. Development of the Cyber-Aggression Detection and Mitigation System
1. The proposed real-time cyber-aggression detection and mitigation system
was successfully developed and implemented as a Chromium-based browser
extension under Manifest V3, integrating a DOM-based text extraction module, a
hybrid Naive Bayes and VADER classification engine, and mitigation features
consisting of text blurring, reveal/re-hide controls, and user-defined blocklist and
whitelist rules.
2. The extension combined the Naive Bayes and VADER-derived scores
using

weighting

(60%
Naive

40%
VADER)
and

language rules, and custom filtering rules that could override the algorithmic
decision.
3. The system's main interface, detection logs and statistics, text-masking
and reveal controls, custom word-list settings, and Expert Mode with PDF export
were all implemented and functioned as intended during the controlled browser
demonstration.


=== PDF PAGE 49 ===

4. Documented functional testing showed that all 70 automated regression

Chrome test and a documented live-website test matrix across major social media
platforms remained incomplete.
2. Comparative Classification Performance of the Hybrid Model
1. The hybrid Naive Bayes and VADER model achieved a precision of
88.82%, a recall of 75.16%, and an F1-score of 81.42% on the 12,980-sample
testing set, compared to a precision of 85.13%, a recall of 77.60%, and an F1-score
of 81.19% for standalone Naive Bayes, and a precision of 57.40%, a recall of
58.43%, and an F1-score of 57.91% for standalone VADER.
2. The hybrid model attained the highest precision and F1-score among the
three approaches, while standalone Naive Bayes attained the highest recall; the
hybrid configuration produced 133 fewer false positives but 79 more false negatives
than Naive Bayes alone, reflecting a trade-off between reducing incorrect aggressive
classifications and detecting the full range of actual aggressive samples.
3. A subsequent comparison of 21 Naive Bayes-VADER weight combinations
showed that the implemented 60/40 weighting ranked sixth of 21 by F1-score,
approximately 0.13 percentage points below the highest-observed configuration of
65% Naive Bayes and 35% VADER (81.55%).

3. Apply a statistical significance test to the hybrid-versus-Naive-Bayes
